# Task 04: Generate Migrations and Verify

## Status

pending

## Wave

4

## Description

Finalize the feature by adding the missing Drizzle migrate workflow, generating migration files for the Better Auth schema, and running project verification. The repo currently has `db:generate`, `db:push`, and `db:studio` scripts but no `db:migrate` script. The repo rules explicitly prohibit `drizzle push`, so this task must use migration generation and migration commands only.

## Dependencies

**Depends on:** task-03-client-signup-integration.md
**Blocks:** None

**Context from dependencies:** Tasks 01 through 03 add Better Auth schema, server handler, and signup client integration. This task validates that the schema can produce migrations and that the integrated app passes lint, typecheck, and build commands.

## Files to Create

- `packages/db/drizzle/*` migration files — generated by Drizzle after schema changes.

## Files to Modify

- `package.json` — add a root `db:migrate` script that delegates through Turbo.
- `packages/db/package.json` — add a package-level `db:migrate` script using `drizzle-kit migrate`.
- `turbo.json` — add a `db:migrate` task with `cache: false`.

## Technical Details

### Implementation Steps

1. Add migration scripts:
   - Root `package.json`: add `db:migrate` with value `turbo run db:migrate`.
   - `packages/db/package.json`: add `db:migrate` with value `drizzle-kit migrate`.
   - `turbo.json`: add `db:migrate` task with `{ "cache": false }`.
2. Run Drizzle migration generation from the repository root using the existing script: `pnpm db:generate`.
3. Run migration application only if `DATABASE_URL` is available and points to a safe local/dev database: `pnpm db:migrate`.
4. Do not run `pnpm db:push`, `drizzle-kit push`, or any command that pushes schema directly without migrations.
5. Run verification commands from the root:
   - `pnpm lint`
   - `pnpm check-types`
   - `pnpm build`
6. If any command fails because of missing environment variables or unavailable database, report the exact failure and leave the code/migration files in place.
7. Optionally verify Better Auth health when the dev server is running by calling `GET /api/auth/ok`; do not block completion if a running server is not available in the agent environment.

### Environment Variables

- `DATABASE_URL` — required for `drizzle-kit generate` because `packages/db/drizzle.config.ts` throws if it is missing, and required for `drizzle-kit migrate` to apply migrations.
- `BETTER_AUTH_SECRET` — required at runtime for Better Auth.
- `BETTER_AUTH_URL` — required at runtime for Better Auth.

### API Endpoints

- `GET /api/auth/ok` — optional runtime smoke test after starting the app.

## Notes

Better Auth docs state that the direct `auth@latest migrate` command is for the built-in Kysely adapter. For Drizzle, generate/update schema and apply changes with Drizzle's migration tooling.
